# SO-101 Teach

SO-101 전용 티칭 프로그램이다. 여섯 서보의 정수 모터 틱을 저장하고, 스텝마다 고정 자세 또는 지그 따라가기를 사용한다. 이 문서는 현재 동작을 설명한다. `verification/`의 날짜별 보고서·스크린샷·`before` 및 `previous-source`는 당시 상태를 보관한 기록이며 현재 설정의 원본이 아니다.

## 실행과 현재 구성

```bash
so101-teach
bash SO101_teach/run.sh --setup  # 설정 화면
bash SO101_teach/run.sh --demo   # USB를 열지 않는 데모
bash SO101_teach/run.sh --camera-only --minimized  # 모터 연결을 차단하고 Pi 카메라만 연결
bash SO101_teach/run.sh --check  # 설정·계산 초기화 검사, 장치 접근 없음
```

PC 경로는 `/path/to/Final_Arm/SO101_teach`, Python은 `/home/fresh/venv/il/bin/python`이다. 실행 중인 앱의 Python 코드는 자동 교체되지 않으므로 변경 후 다시 실행한다. 3D 렌더링 기본값은 EGL이며 별도 GLFW 렌더 창을 만들지 않는다. 필요한 경우 `MUJOCO_GL=glfw bash SO101_teach/run.sh`로 명시적으로 바꿀 수 있다. 선택한 팔과 장치 연결 대상은 저장된다. Pi 연결 실패 시 PC USB로 자동 전환하지 않는다.

| 구분 | 현재 구성 |
|---|---|
| Pi | `ubuntu@10.10.142.113`, `/home/ubuntu/OpenCV_teach` |
| Pi Python | `/home/ubuntu/so101-player/.venv/bin/python` |
| 로봇팔2 | Pi USB `…5B91027630-if00`, 실측 보정 완료 · 팔별 A/B 에피소드 |
| 로봇팔3 | Pi USB `…5B91028218-if00`, 실측 보정 완료 · 팔별 A/B 에피소드 |
| 리더 | PC USB와 별도 보정 파일 사용 |
| 영상 / 3D | 촬영·검출·전송 최대 10 FPS / 3D 최대 30 FPS |

보정이 완료된 팔은 시작 시 읽기 연결을 시도한다. 연결만으로 토크·이동·리더 따라가기를 켜지 않는다. 팔3의 보정 완료 여부는 `robot_profiles.json`의 상태와 실제 적용 결과로 판단한다. 상단의 **전체 연결** 버튼으로 두 팔을 함께 연결한다. 이미 연결된 팔은 유지하고 연결되지 않은 팔만 준비한다. 상단의 팔2·팔3 버튼으로 작업 화면을 바로 바꾼다. 두 팔은 각각 연결을 유지하며, 선택을 바꿔도 다른 팔의 토크와 실행 중인 에피소드는 계속된다. 새 조작 명령은 선택한 팔에만 보낸다. 보정 작업·리더 따라가기 중에는 해당 작업을 마친 뒤 전환한다. 공유 카메라는 한 팔씩 사용하고 다른 팔의 측정은 순서대로 기다린다. 각 팔의 마지막 에피소드·편집·지그 고정값도 별도로 유지한다. **실물값 보기**에서는 두 팔의 최신 측정값을 각자의 보정값으로 변환해 표시한다. 선택을 바꿔도 실물값 보기를 유지하며, 수신이 끊기거나 보정이 일치하지 않는 팔은 실물 표시에서 숨긴다. **스텝 자세와 3점 각도 보정**에서 다른 팔은 저장된 시작 안전 자세로 고정한다. 저장된 안전 스텝이 없으면 화면에 기준 자세임을 표시한다. 표시만 바꾸며 실제 팔을 이동시키거나 모터 틱을 복사하지 않는다.

카메라 전용 실행은 모터·리더 자동 연결, 토크·이동 명령, 모터 보정을 차단한다. 두 팔의 Pi 에피소드를 읽어 온 뒤 선택한 팔의 카메라를 연결한다. `--minimized`를 함께 쓰면 작업 중인 창 앞으로 올라오지 않는다. 일반 실행으로 다시 시작해야 모터를 연결할 수 있다.

## 티칭과 편집

시작 시 각 팔의 Pi 에피소드·완료 알림·실행 설정을 불러온다. Pi 원본이 마지막 조회 때와 같으면 로컬 검토 설정을 그대로 유지한다. Pi 원본도 바뀐 경우에는 로컬 수정본을 별도로 보존한 뒤 새 원본을 불러온다. **스텝 추가·편집** 탭에서는 자세를 편집하고, **에피소드 조정** 탭에서는 완료 알림과 실행 설정을 조정한다. Pi 반영은 **설정 내보내기**에서 선택한 팔과 내용을 확인한 뒤 수행하며 단순 연결·선택으로 업로드하지 않는다.

1. 상단에서 팔을 선택하고 **설정·안내 → 로봇**에서 포트·팔로워/리더 보정 파일과 동작 모드를 확인한다.
2. 에피소드를 선택하거나 새로 만든다. 팔2의 에피소드는 팔3 목록에 표시하지 않는다. 다른 영점의 기존 기록을 자동 변환하지 않는다.
3. **실물 자세 추가** 또는 **Space**로 읽은 최신 위치를 저장한다. Space는 1초 간격이며 길게 눌러도 한 번만 저장한다. 입력칸에서 Space는 저장 단축키가 아니다.
4. **실물값 불러오기**는 측정값을 편집칸으로 복사한다. 실물 조정을 시작하지 않은 상태에서 숫자·화살표로 편집한 틱은 미리보기에만 적용된다.
5. **새 스텝 추가**는 새 기록을 만들고, **선택 스텝 수정**만 기존 스텝을 바꾼다. 직전 스텝과 이름·틱·지그 기준이 모두 같으면 중복 추가하지 않는다.
6. 스텝은 드래그로 순서를 바꾼다. 왼쪽 클릭은 편집 1, 오른쪽 클릭은 편집 2로 불러온다. 3D는 마지막으로 조작한 편집창의 자세를 표시한다. 편집 2를 닫는 것만으로 저장하지 않는다.

**Z**는 초점이 있는 편집창의 지그 따라가기를 켜고 끈다. 기존 기록·모터·확정 위치는 변경하지 않는다. 이름·숫자 입력 중이나 안전 자세 편집 중에는 이 단축키를 적용하지 않는다.

에피소드 복사는 별도 ID를 만든다. 삭제는 선택한 에피소드 파일과 화면 상태를 정리하며, 관련 실행 기록·진단 파일은 자동 삭제하지 않는다. 저장된 에피소드는 모터 틱, 팔 ID, 보정 파일 해시, 각 스텝의 지그 기준을 보관한다.

액션 실행 오류가 발생하면 정지 처리를 먼저 수행한 뒤 `data/diagnostics/action-failures/<날짜-실행 ID>/`에 영상과 `error.json`을 저장한다. 검사 오류는 판정에 사용한 수신 영상(`inspection.jpg`)을 우선 저장하고, 지그 검출 영상(`detection.jpg`) 또는 마지막 수신 영상(`last-received.jpg`)을 구분해 남긴다. JSON에는 촬영 시각·오류까지 경과 시간·오류 내용·실행/스텝 정보·검사 결과·당시 설정과 확정 지그 위치·프로그램 버전을 기록한다. 판정 영상이 캐시에 없으면 마지막 영상을 해당 판정 영상으로 표시하지 않으며, 수신 영상이 없는 오류는 사유만 남긴다. 저장 영상은 Pi에서 이미 수신한 JPEG이며 센서의 무압축 원본은 아니다. 오류 후 사진을 얻기 위해 카메라를 다시 연결하지 않는다. 실행 이력의 `FAILURE_IMAGES`와 검사 로그의 `failure_evidence`에서 저장 위치를 찾을 수 있다. 저장 실패는 별도 이벤트로 남기고 기존 오류·정지 처리를 유지한다. 정상 실행 중에는 최근 32장만 메모리에 보관하며 자동 이미지 파일은 실패 시에만 생성한다. 저장된 실패 기록은 자동 삭제하지 않는다.

**상단 카메라 → 오류 기록**에서 Pi 또는 이 PC의 최근 오류 최대 200건을 조회한다. 팔별 필터와 날짜·작업·오류 내용 검색을 지원하며, 목록을 선택하면 저장 이미지와 오류·실행 로그를 함께 표시한다. 검사 영상과 마지막 수신 영상을 구분하고 촬영 시각·오류까지 경과 시간을 표시한다. 이미지 확대·맞춤·드래그 이동, 요약/전체 JSON 보기, 로그 복사를 제공한다. 이미지가 없는 과거 액션 실패도 실행 로그를 볼 수 있다. 조회는 별도 SSH 파일 읽기로 처리하며 카메라·모터 연결을 시작하지 않는다. 새 오류는 **새로고침**으로 불러온다.

## 사진 촬영과 저장 사진 보기

**상단 카메라 → 영상 저장**에서 왼쪽 실시간 원본과 오른쪽 저장 사진을 함께 본다. 큰 **사진 촬영·저장** 버튼으로 원본 PNG·화면 표시본 PNG·판정 JSON을 `data/captures/원본`, `화면 표시본`, `판정 기록`에 같은 촬영 이름으로 저장한다. Pi 모드의 원본은 Pi에서 전송받은 영상이며 센서의 무압축 RAW 파일을 뜻하지 않는다.

아래 촬영 목록은 최신순이며 사진을 선택해 바로 볼 수 있다. 새 사진을 저장하거나 발견하면 그 사진을 우선 표시하고, 새 사진이 없으면 사용자가 고른 사진을 유지한다. 원본·화면 표시본 전환을 지원하며 카메라를 꺼도 저장 사진은 계속 볼 수 있다. 사진이 없거나 파일이 사라졌으면 안내를 표시한다.

사진 촬영·저장 버튼은 **좌클릭으로 저장**, **우클릭으로 목록에서 선택한 사진의 원본·화면 표시본·판정 기록을 함께 삭제**한다. 새 촬영 직후에는 방금 저장한 사진이 선택되어 있으므로 우클릭 한 번으로 지울 수 있다. 카메라가 끊겨도 선택 사진을 삭제할 수 있다. 우클릭 더블클릭은 0.2초 동안 한 번만 처리하여 다음 사진까지 연달아 지우지 않는다.

촬영 버튼의 문구·크기는 고정하며 저장 대기 때문에 활성 표시를 빠르게 전환하지 않는다. 완료 내용은 하단 안내에 표시한다. 저장 성공 후 0.2초간 재촬영을 막고 같은 카메라의 이미 저장한 프레임을 중복 저장하지 않는다. 새 프레임 수신과 대기 시간 경과를 모두 만족해야 다시 촬영한다. 지그 검출·부품 검사 탭의 저장에도 같은 제한을 적용한다. 저장 실패는 재시도를 막지 않으며, 같은 배치의 유사한 새 프레임까지 자동 제거하는 기능은 아니다.

실물 학습용 사진은 표시 없는 **원본**을 사용한다. 촬영 예시와 기록 표는 [상단 카메라 사진 촬영 예시표](docs/상단카메라_사진촬영_예시표.md)를 따른다. 사진 촬영과 실물 자세를 저장하는 Space 단축키는 별개다.

## 지그 기준과 각도

**지그 관리**에서는 등록된 지그의 이름·STL·받침 높이를 수정한다. 새 지그 추가·복사 기능은 제공하지 않는다. 검출 방식·형태·단위는 모델별로 고정한다. 운반용 지그(220×148mm)는 직사각형·외곽+교차점, 완제품 팔레트(70×70mm)는 도넛형·윤곽+돌출 모서리를 사용하며 단위는 모두 mm다. 해당 선택 항목과 STL 없는 수동 치수 입력은 제공하지 않는다. 기존 저장값도 같은 고정 조합으로 읽으며 사용하지 않는 수동 치수 항목은 정리한다. 파일을 선택하거나 같은 경로의 STL이 다시 생성되면 오른쪽 미리보기가 갱신된다. **지그 저장** 전에는 등록 설정이 바뀌지 않는다. 저장할 때 기존 ROI와 설치 정보를 유지한다. 등록된 운반용 지그는 메인 시뮬과 같은 방향·버거·고정부 조립을 표시한다.

| 모델 | 방향 판단 |
|---|---|
| 정사각형 팔레트 | 90° 대칭. 0° 이상 90° 미만으로 표시하며 티칭값에 가장 가까운 방향으로 보정 |
| 일반 직사각형 | 180° 대칭 |
| 운반용 조립 지그 | A 상단의 고정 원형 구멍을 확인해 360° 방향을 구분 |

팔레트의 89°→1° 변화는 +2°로 계산하며, 정확한 90° 회전은 같은 자세다. 운반용 지그는 원형 특징을 확인하지 못하면 임의 방향을 채택하지 않는다. 내부에 놓인 제품 자체의 방향·종류를 검사하는 기능은 아니다.

2026-10-12 운반용 지그의 외곽 보정 성공 여부에 따라 서로 다른 위치가 선택되던 문제를 수정했다. 일반 윤곽 후보도 같은 외곽 보정을 거치며, 세 변이 충분히 보이고 나머지 한 변에서도 길이 35% 이상에 걸쳐 24개 이상의 실제 경계점이 확인돼야 한다. 어두운 영상에서는 검출된 운반판 내부의 밝기를 기준으로 재질 경계를 확인한다. 외곽을 확인하지 못한 프레임은 미검출로 처리하고, 내부 경계에 맞은 기존 후보로 되돌아가지 않는다. 크기·방향·ROI 검증과 부품 안착 허용 오차는 유지한다. 서로 다른 저장 영상의 전체 검출·위치 확정과 일반 윤곽 경로를 회귀 검사하며, 실물 이동 검증은 포함하지 않는다.

**자동 갱신 정지**는 확정 측정값을 시간 제한 없이 유지한다. 현재 에피소드의 모든 스텝에서 사용하는 지그를 중복 없이 모아 채택 여부를 확인한다. 선택한 스텝·편집기·카메라 보기로 이 범위를 좁히지 않으며, 에피소드에서 사용하지 않는 등록 지그는 기다리지 않는다. 다만 정지 요청 시 이미 유효하게 채택된 지그와 대기 중 새로 채택된 지그는 에피소드 사용 여부와 관계없이 함께 고정·유지한다. 정지 조건에 쓰는 목록과 유지할 채택값은 별도로 관리하며, 요청 전에 이미 만료되거나 무효화된 탐지값을 되살리지는 않는다. 하나라도 미채택이면 `에피소드 지그 채택 중`으로 표시하고 측정을 계속하며, 대상 지그가 모두 채택된 뒤 정지 상태를 켠다. 고정 스텝만 있는 에피소드는 지그 채택을 기다리지 않는다. 아직 스텝이 없는 새 에피소드는 첫 티칭을 위해 현재 선택 지그(카메라 전체 보기에서는 전체 지그)를 기준으로 한다. 측정 실패 시에는 자동 갱신을 계속하고 실패 대상을 안내한다. 정지 중 새 스텝 저장·개별 이동·경로 미리보기·리더 따라가기는 이 고정값을 사용한다. 개별 이동·미리보기·따라가기는 고정값이 없는 지그만 한 번 읽으며, 새 스텝 저장은 먼저 지그 다시 읽기가 필요하다. 전체 에피소드 실행은 매번 새로 측정하지만 티칭 고정값을 바꾸지 않는다. **지그 다시 읽기**는 선택한 지그의 고정값만 갱신한다.

정지 중에는 윤곽 검출을 멈추고 카메라 화면의 원본 영상만 최대 5fps로 갱신한다. 다시 읽기·전체 실행 전 측정·자동 갱신 재개 시 검출과 영상 갱신을 최대 10fps로 복구한다. 화면을 벗어나고 측정 작업도 없으면 카메라와 영상 전송을 끈다. 보정용 사진은 검출 없이 수집한다.

새 위치에서 다시 확정하면 이후 추가하는 스텝부터 그 기준을 저장한다. 갱신 중에 같은 지그의 스텝을 추가하면 마지막으로 저장한 해당 지그 기준을 이어 쓴다. 기존 스텝을 선택·수정·이동할 때는 그 스텝의 원래 기준을 사용한다. **지그 다시 읽기**는 기존 티칭 기준을 덮어쓰지 않는다.

지그 따라가기 계산은 티칭한 TCP의 지그 상대 XY와 방향을 현재 지그에 옮긴다. 목표 Z와 집게 J6 틱은 유지하고 J1~J5를 다시 계산한다. 동일 지그 위치·각도이면 원래 틱을 유지한다. 계산 위치 오차 3mm 또는 자세 차이 45°를 넘으면 실행하지 않는다. 티칭 기울기와 이전 스텝의 자세 연속성을 고려하고, 가능한 몸체 관절에 3° 한계 여유를 확보한다. 수치 잔차는 모델 계산 결과이며 실물 파지 정확도 검증값이 아니다. 상세 식과 기준 수명은 [JIG_FOLLOWING.md](JIG_FOLLOWING.md)에 있다.

카메라 보정 화면은 현재 렌즈 보정에 사용한 사진 폴더·목록·사진별 오차를 자동 복원한다. 사진을 더블클릭하면 원본을 확인한다. 원본이 없으면 목록에 파일 없음을 표시하며 기존 보정값은 유지한다. 사용 사진 기록이 없는 외부 보정값도 구분해 표시한다.

## 측정과 카메라

새 측정 중 촬영·검출·전송은 최대 10 FPS이며 처리 부하에 따라 실제 속도는 낮아진다. 영상 통신과 제어 통신을 분리한다. 화면은 최신 영상을 표시하고 검출 결과의 촬영 시각을 유지한다. 오래된 위치를 새 측정값처럼 사용하지 않는다.

- **획득 시간:** 3~10초, 기본 3초. **최대 시도:** 1~5회, 기본 3회. **실행 기준 유지:** 1~10초, 기본 10초.
- 한 구간의 서로 다른 관측을 모아 중심 5px·방향 3°·면적 12% 범위의 최다 과반 그룹을 찾고 위치·방향 중앙값을 채택한다. 최소 2회, 약한 후보는 최소 3회가 필요하다.
- 실행·지그 측정에는 촬영 후 **3초 미만**인 검출 결과를 사용한다. 실행 요청 이후 새로 채택된 위치여야 하며, 원본 촬영 시각은 처리·전송 후에도 유지한다. 사진 촬영과 실시간 미리보기의 영상 신선도 기준은 별도다.
- 2회 미만·위치 불일치·동률·최신 방향 미확인은 실패다. 모든 시도가 끝나면 **지그 다시 읽기**로 새 획득을 시작한다. 카메라 연결 시간도 전체 획득 예산에 포함한다.
- 지그별 ROI는 **사각형 / 자율 영역**으로 지정한다. 오목한 영역은 지원하지만 자기 교차·너무 작은 영역은 저장하지 않는다. 우클릭 또는 취소로 기존 범위를 유지한다.
- 팔레트는 외곽·중앙 구멍·STL 치수를 함께 확인한다. 흐린 외곽 한 변 때문에 후보가 탈락하면, 나머지 세 변과 중앙 구멍이 충분히 보이고 높이를 반영한 네 모서리 돌출부가 모두 맞을 때만 보완한다. 모서리만으로 위치를 추정하거나 이전 검출값을 새 관측처럼 사용하지 않는다.
- **전체 지그**는 모든 지그의 검출·채택 상태를 함께 표시한다. 최신 프레임의 외곽 점선과 채택한 위치의 실선·십자를 구분한다.
- **영상 저장**은 화면의 ROI·외곽·중심·좌표를 포함한 합성 이미지를 저장한다. 사진은 `data/captures`, 측정 정보는 `data/captures/metadata`에 있다.

렌즈 보정은 내부 코너 13×9, 간격 20mm 체커를 기본으로 사용한다. 카메라 내부 보정과 카메라→로봇 좌표 연결은 서로 다르다. 장착 위치·각도가 바뀌면 좌표 연결을 다시 확인해야 한다. 계산은 작업 스레드에서 수행하며 검사 결과로 기존 보정을 임의 교체하지 않는다. 계산 중 팔·카메라 설정이 달라졌다면 결과를 적용하지 않고 다시 계산한다. CAD 카메라 좌표 복원은 선택 팔의 배치·설치 높이를 반영한다. Pi 연결 중 보정 적용은 Pi 성공 후 로컬에 저장하므로 거부된 값을 로컬에 먼저 확정하지 않는다.

## 실행과 정지

**현재 자세 유지 · 토크 켜기** 후 이동·실행 버튼을 사용한다. 연결·미리보기·설정 변경은 별도 동작이다.

| 조작 | 동작 |
|---|---|
| 경로 미리보기 | 실물 구동 없이 같은 지그 보정 계산을 표시 |
| 이 자세로 이동 / 실물 조정 | 현재 확정한 지그 위치를 유지해 선택 자세로 이동 |
| 에피소드 실물 실행 | 시작 안전 자세 → 사용 지그 새 측정 → 작업 스텝 → 종료 안전 자세 |
| 티칭 그대로 실행 · 보정 없음 | 카메라·지그 보정 없이 저장 틱 그대로 실행 |
| 이동 정지 · 자세 유지 | 현재 측정 위치에서 힘 유지 |
| 토크 해제 / Esc | 모터 힘 해제 |

안전 자세는 사용자가 저장한 고정 틱이며 시작·종료가 같다. 안전 자세로 이동하지 못하거나 지그를 채택하지 못하면 다음 작업을 시작하지 않는다. 지그가 없는 고정 스텝만 실행할 때는 측정이 필요 없다. 실물 조정은 숫자·화살표 입력을 한 번에 최대 50틱으로 제한한다. 실제 조정 중 다른 스텝·화면으로 바꾸면 조정을 멈춘다.

속도는 **느리게 300 / 보통 350 / 빠르게 400틱/초**이며 기본은 보통 350틱/초다. 기존 속도 설정은 처음 열 때 이 기본값으로 맞춘다. 앞뒤 각각 10% 구간에서 짧게 가감속하고, 일반 경유점은 속도를 이어가며 안전 자세·집게 동작 전후·마지막 지점에서는 정지한다. 미리보기 별도 배속 선택은 없다.

도착 기준은 몸체 ±20틱, 집게 ±30틱에서 0.2초 유지다. 부하로 목표 근처에서 멈추는 어깨·팔꿈치는 원래 목표를 유지하면서 최대 64틱의 명령 보정을 초당 12~40틱으로 적용한다. 에피소드의 몸체 잔여 오차가 ±32틱 이내이고 집게·모터 상태가 정상이라면 오차를 기록하고 다음 스텝으로 진행할 수 있다. 리더 따라가기·집게에는 이 보정을 적용하지 않는다.

집게는 닫는 중 설정 부하에 도달하면 접촉 틱을 유지하며 목표까지 강제로 닫지 않는다. 기본 임계값은 원시 부하 80이다. 장비 화면의 부하 %는 1023=100% 환산이며 실제 힘·최대 토크의 비율이 아니다.

## 에피소드 완제품·시작 전 조건·스텝 검사

**티칭 → 에피소드 조정** 상단의 **에피소드 공통 · 완제품**에서 A/B를 한 번 선택한다. 완제품 종류는 모든 스텝과 시작 전 검사에서 공통으로 사용한다.

**시작 전 검사**에는 운반대의 선택 제품 부품 전체(3개), A/B 부품 전체(6개), 개별 부품 안착과 리니어·완성품 팔레트의 부품 유무 등을 조건으로 추가한다. 지그 검출 직후 검사하며 모두 통과해야 안전 자세 이동·로봇 스텝을 시작한다. Pi에서는 리니어 이동과 지그 검출을 병행하고, 고정 지그의 시작 전 검사는 리니어 이동 중에도 진행한다. 리니어 위 검사는 리니어 정지 후 진행한다. 부품 전체는 같은 영상에서 함께 계산한다. 부품별 동일한 유효 판정이 최소 횟수(기본 2회, 2~10회 설정 가능)를 충족하면 확정하고 다음 계산에서 제외한다. 결과 없음·판정 불가는 횟수를 늘리지 않으며, 제한시간(2~30초)은 부품별로 적용한다. PC에서는 현재 자세 유지 상태에서 검사하고, Pi는 읽기 연결 또는 자세 유지 상태에서 검사한다. 리니어는 제어기의 완료된 명령 위치를 조회하며 위치 센서 실측은 아니다.

**스텝 도착 후 검사**에서는 왼쪽 목록의 일반 스텝을 선택하고 검사 위치(운반용 지그·리니어 조립·완성품 팔레트), 대상, 기대 상태, 제한시간을 저장한다. 리니어 좌측 팔레트는 A용, 우측은 B용이다. 종류·조립 단계를 검사할 때는 해당 팔레트의 제품 종류를 적용한다. ‘부품 있음’은 존재만 검사하며 정상 안착과 구분한다. ‘부품 없음’은 빈 팔레트 형상이 확인돼야 통과하고 가림·미검출을 빈 상태로 취급하지 않는다.

검사를 지정한 놓기·들기 스텝의 다음 스텝에 팔과 집게가 검사 영역을 벗어나는 자세를 둔다. 그 다음 스텝 완료 후 검사를 시작한다. 검사 스텝 뒤에 다음 스텝이 없으면 실행을 거부한다. 스텝 검사는 이름·순서 변경 시 유지되며 해당 스텝을 삭제하면 함께 삭제된다. 시작 전 조건은 에피소드에 따로 저장된다. 기존 에피소드에는 검사가 자동 추가되지 않는다.

검사 포함 에피소드도 전체 경로를 연속 실행한다. 지정 스텝 다음 스텝이 완료되면 새 영상에서 기존 형상·ROI·중심 이탈 기준으로 판정하며, 검사 중에도 이후 동작을 계속한다. 같은 제품·기대 상태의 정상 결과가 서로 다른 새 영상에서 설정한 최소 횟수만큼 확인돼야 검사 통과로 기록한다. 모든 검사 통과 전에는 최종 작업 완료를 보내지 않는다. 과거 화면 판정과 저장된 티칭 위치만으로 검사를 통과시키지 않는다. 불합격·다른 제품·카메라 오류·판정 시간 초과 시 오류를 기록하고 현재 자세를 유지하며 실행을 중단한다. 검사 실패 후 자동으로 재개하지 않는다. 2026-10-11부터 형상 후보의 점수 차이가 부족한 `판정 불가`는 대기 상태로 처리한다. 실행 중에는 마지막 정상 관측에서 1초 이내인 불확실한 프레임을 건너뛰어 유효한 정상 관측을 모으며, 불확실한 프레임이 관측 유효 시간을 늘리지는 않는다. 실제 경계 걸침·오안착·다른 제품 판정과 원래 검사 제한 시간은 유지한다. A/B 종류 구분 근거 부족도 확인 대기이며, 실제로 다른 제품이 확인된 경우와 구분한다. CAD 윗면 비교에는 카메라에서 부품 뒤에 가려지는 낮은 지그 경계선을 제외해 완제품 윗면에 존재하지 않는 홈을 요구하지 않는다. 이 가림 처리는 운반대·리니어·완제품 판정에 공통 적용하며 위치·방향·ROI 허용 기준은 유지한다.

PC의 에피소드 실행과 티칭 그대로 실행 모두 검사를 적용한다. Pi의 A/B 실행에서는 검사 통과 뒤 해당 완료 알림을 보내며, 실패 시 `FAILED`를 보고하고 후속 스텝·정상 완료·정상 종료 토크 해제를 수행하지 않는다. 검사 설정이 없는 기존 에피소드는 종전처럼 실행한다. 완제품 종류·검사 설정은 **Pi 에피소드 내보내기**로 전달하며, 검사를 지원하지 않는 Pi에는 전송을 거부한다. 실제 검사 기록은 각 실행기의 `data/diagnostics/episode-inspection-*.json`에 저장한다.

이는 윗면 영상의 형상·위치 검사다. 내부 안착 깊이·결합 강도를 확인하는 센서 판정은 아니다. 카메라 탭의 일반 모니터링 결과만으로 실행을 중단하지 않으며, 에피소드에 지정한 검사에서만 실행을 차단한다.

## 3점 각도 보정과 TCP

**설정·안내 → 3점 각도 보정**에서 선택한 팔로워 또는 리더를 보정한다. 몸체 5개 관절은 0°·음수·양수 기준을 기록한다. 음수 틱 < 기준 틱 < 양수 틱이어야 하며 영점을 다시 기록하면 해당 관절의 양쪽 기준도 다시 측정한다. 기준점 사이와 바깥에서는 구간별 선형식을 사용하며 기계 범위를 유지한다.

집게는 **−90° 기준을 2047틱**으로 기록하고 닫힘·열림 끝점을 측정한다. 집게의 각도 비율은 4096틱/회전이며, 끝점 측정으로 그 비율을 새로 추정하지 않는다. 리더 따라가기는 몸체 각도와 집게 닫힘~열림 비율을 각각 변환한다.

각도 보정 화면의 현재 기준/읽은 각도는 큰 숫자로 표시한다. 팔로워 모델은 선택한 팔의 실제 작업대 배치를 사용하며, 팔3 기본 시점은 벽 반대편의 측면이다. 다른 팔에 유효한 저장 안전 자세가 있으면 그 자세로 표시한다. 기준각 버튼·시점 조절은 표시만 바꾸며 모터를 움직이지 않는다.

보정 시작은 토크 OFF와 서보 설정 변경을 포함하는 별도 작업이다. 중단하면 이전 서보 설정을 복원하고 진행 기록을 보관한다. 최종 저장 후에는 앱 안내에 따라 전원을 껐다 켜고 재연결한다. 새 영점으로 기존 에피소드 틱을 자동 변환하지 않는다. JSON과 같은 이름의 `.angles.json`을 함께 보관한다. 팔3의 초기 연결용 템플릿은 실측 보정을 대신하지 않는다.

TCP는 **고정 집게 끝단 / 고정 집게 중앙 / 직접 설정** 중 선택한다. 모델 끝단 좌표는 `gripper_frame_link` 기준 약 `(1.773410, 0.602657, 6.549655)mm`, 중앙은 `(0,0,0)`이다. TCP 입력은 미리보기만 바꾸며 **TCP 적용·저장** 후 계산에 반영한다. 연결 중에는 토크 OFF·최신 상태를 확인하고 Pi 적용 성공 후 로컬에 저장한다. Pi는 TCP뿐 아니라 작업대·카메라·모델 좌표 변경에도 같은 확인을 적용하며, 연결된 3점 각도 보정이 달라지면 재연결을 요구한다. 3점 보정이 있으면 기존 관절 Δ틱 보정은 중복 적용하지 않는다. 관절 Δ틱은 팔별 모델 기준에 저장되어 팔 전환·재시작 후에도 유지된다.

## 리더·통신·장비 상태

**장비 모니터링**은 최대화 화면에서 두 팔의 상세 상태를 나란히 표시한다. 현재·목표 틱과 각도, 토크, 전압, 온도, 부하 원시값과 %, 전류 원시값, 상태를 한 표에서 읽는다. 각 팔의 연결·영점 정보, 장비 알림, 진단 기록 버튼과 공통 중단 기준 설명도 같은 화면에 둔다.

리더는 PC, 선택한 팔로워와 카메라는 Pi에 연결할 수 있다. PC에서 리더 틱을 최대 초당 50회 전달하고 Pi에서 변환한다. 리더 입력이 0.5초 늦으면 위치를 유지하며 기다리고, 2초 이내 복구 시 속도를 제한해 이어간다. 2초 이상이면 직접 다시 시작해야 한다. 에피소드 실행 중에는 리더 전송을 쉰다.

장비 읽기는 일시적인 응답 손상·유실에 최대 3회 재시도한다. 모터 쓰기 응답이 유실되면 해당 레지스터를 읽어 적용 여부를 확인한다. 처리 여부를 모르는 이동·토크 RPC는 자동 재전송하지 않는다. 0.1초 미만 전압 경고는 기록만 남기고, 지속되면 알린다. 리더는 전압 경고만으로 연결을 끊지 않으며 팔로워의 지속 경고·온도·통신·추종 오류는 실행 중단 조건을 따로 적용한다.

PC 응답이 2초 이상 끊기면 Pi가 이동을 멈추고 자세를 유지한다. 재연결만으로 이동을 재개하지 않는다. Pi 연결·설정·버전 정책은 [PI_SETUP.md](PI_SETUP.md)를 따른다. 실물 읽기 점검은 PING·READ·SYNC_READ만 허용하는 전송 게이트를 사용한다.

리더 어깨·팔꿈치 무게 보조는 보정된 전용 모드다. 일반 읽기·티칭과 구분하며 명시적으로 켰을 때만 동작한다. 보조 전환과 팔 전환은 실행·토크 상태를 확인한다.

## 좌표·현재 모델·작업대

저장·역기구학은 선택한 팔의 로봇 베이스 좌표를 사용한다. **로봇팔 높이 보정은 원점이 높아질수록 +값이며, 직접 설치 0mm·상단 마운트 결합 +5mm**를 기준으로 한다. 직접 설치 0mm는 내부 작업대 Z −2.4mm, 마운트 +5mm는 −7.4mm에 해당한다. 0→+5mm 변경은 팔 기준 작업대 Z를 5mm 낮추고, 같은 관절 자세의 바닥 기준 TCP 높이를 5mm 높인다. 내부 저장·Pi 전송은 작업대의 절대 Z를 유지하므로 기존 저장값을 자동 반전하지 않는다. 같은 내부 좌표를 유지하면 이전 0mm 표시는 새 기준 +5mm, 이전 +5mm 표시는 새 기준 0mm가 된다. 높이 적용 시 선택 팔의 월드 위치와 카메라→팔 변환도 함께 이동해 공통 작업대·카메라·다른 팔은 고정한다. 적용·저장 시 선택한 팔의 설정과 Pi 계산 기준을 함께 갱신한다. 팔 번호가 아니라 실제 설치 방식에 맞춰 설정한다. 화면 표시 XY는 `(-Y로봇, X로봇)`, 방향은 `(θ로봇+90°) mod 대칭주기`다. 예전 운반용 지그 내부 방향 약 29°는 화면에서 약 119°로 보이며 같은 자세다. 조립 STL의 방향 차이 180°는 별도 모델 방향 보정값으로 관리한다.

2026-10-11 운반용 지그에 새 **B 하단·B 상단**을 반영했다. 조립 STL SHA-256은 `23f8ddb6d925c8c15f5ec543804dc42c2db10bc356cfcdaa45742b1c0e04f4d9`이다. B 하단 벽 높이는 8.5→15.5mm로 바뀌었지만 CAD 부품 안착 높이·중심, 운반판 외곽·검출 높이·A 방향 구멍은 같다. 리니어 조립 지그는 기존 형상을 `assets/linear_stage/assembly_fixture.stl`로 분리해 유지한다. 이전 모델을 참조하는 에피소드는 검증된 동일 좌표·방향 기준으로 해석하며 저장 위치·각도·모터 틱·기록은 변경하지 않는다. 알 수 없는 모델·방향 기준은 허용하지 않는다. 새 지그는 아직 실물 미설치이며 이번 검증은 CAD·합성 영상·기존 사진 회귀 기준이다. 설치 후 실제 카메라와 집게 간섭 확인이 필요하다.

운반판 기준 위쪽 B 3개·아래쪽 A 3개, 각 행 왼쪽부터 상단·중단·하단이다. 버거 정면에서 보는 사진 기준 A가 앞줄, B가 뒷줄이다. 앱의 받침 높이 0mm는 작업대 윗면과 같은 높이를 뜻한다. 실제 바닥 기준 작업대 윗면과 운반판 아랫면은 195mm, 운반판 검출 테두리는 199.8mm다. [완성품 STL](assets/carrier_assembly/carrier_assembly.stl)과 [조립 설명](assets/carrier_assembly/README.md)을 참조한다.

리니어는 L12-100-100-6-R, 300mm 레일과 두 지그가 함께 움직이는 이동판으로 표시한다. 전진 명령은 100mm, 후진 명령은 1.5mm이며, 카메라로 맞춘 이동판 위치는 각각 약 54.349mm, −41.916mm다. Pi 모드에서는 ROS의 마지막 명령 상태를 상시 구독하고 두 팔 화면이 수신부 하나를 공유한다. 전후진 명령이 바뀌면 하단 상태와 이동판 배치를 함께 갱신한다. ROS 상태가 1초 넘게 없거나 SSH 수신이 끊기면 마지막 명령을 수신 끊김과 함께 표시하며 자동 복구한다. 최종 명령은 앱과 독립적인 Pi 리니어 제어기가 파일에 기록한다. 같은 목표를 다시 받으면 PWM 재출력과 타이머 연장을 생략하며, 재시작 후에도 저장된 명령을 상태로 발행한다. 앱은 이를 읽어 표시한다. 실제 위치·도착을 측정했다고 표시하지 않는다. 처음부터 상태가 없으면 저장된 기준 배치임을 명시한다. 작업대·다리·버거·리니어·다른 팔의 표시용 조립은 실제 충돌 검증이나 기계 보정을 대신하지 않는다.

## 시뮬레이션 원본과 내보내기

2026-10-13 A/B 실물 시험 후 사용자 요청으로 **앱과 Pi의 실행 계산을 기존 식으로 복구**했다. 두 팔 모두 `geometry.Kinematics`와 원래 `ModelReference`를 사용한다. 지그 보정의 TCP 목표·FK·IK·모터 틱 변환에 새 시뮬 각도 보정을 적용하지 않는다. 독립 실행과 BUILD_LOAD_A/B는 같은 기존 계획기를 사용하며, 지그 이동이 없으면 원래 티칭 틱을 유지한다.

새 각도 보정은 3D 시뮬레이션 표시에만 유지한다. 화면의 **시뮬 보정 적용**과 **실행은 기존 식** 문구로 구분하며, 보정된 3D 표시를 실물 실행 정확도로 해석하지 않는다. `assets/joint_alignment/`의 보정 데이터와 `ExecutionKinematics`는 시뮬 표시·과거 시험의 오프라인 재현용으로 보존한다. 앱·Pi 실행 경로는 이 시험 클래스를 사용하지 않는다. 저장된 에피소드·모터 보정·지그 값과 오류 이미지 원본/판정 표시본 저장은 유지한다. 복구 후 앱을 다시 실행해야 한다.

복구 검증과 Pi 배포 기록은 `verification/restore_original_ik_20261013/`에 있다.

로봇팔 선택은 조작 대상과 팔별 작업 데이터만 전환한다. 현재 상위 탭·설정 하위 탭·실물/스텝 보기·3D 시점은 유지하며, 다른 팔의 연결·토크·진행 중인 동작은 보존한다.

### 팔레트·지그 중심 표시

리니어 전후진 기준 좌표는 기존 시뮬 배치와 모터에서 먼 팔레트 중심을 사용합니다. 팔레트 중앙은 캐리지 로컬 X=40mm, Y=0mm, Z=13.65mm(설치 9.4 + 모델 중심 4.25)입니다. 전후진 기준점과 F/R 문구는 화면에 표시하지 않습니다.

현재 팔레트 중심만 `Pallet 1`(모터 쪽), `Pallet 2`(끝막이 쪽)로 표시합니다. 등록 지그는 등록 순서대로 `Jig 1`, `Jig 2` 등의 중심을 표시하며, 위치가 없거나 숨겨진 지그의 중심은 표시하지 않습니다. 중심 높이는 각 CAD 모델 높이의 절반입니다. 글자는 강조 테두리 없이 표시합니다.

**실물값 보기**의 지그는 유효한 현재 탐지 확정값을 우선 표시합니다. 현재 확정값이 없고 실행 기준이 남아 있으면 해당 기준을 표시합니다. **스텝 자세**에서 지그 따라가기 스텝을 선택하면, 유효한 탐지값이 있을 때 실제 실행과 같은 계산식으로 보정한 팔 자세와 현재 지그 위치를 표시합니다. 해당 지그를 탐지하지 못하면 저장된 팔 자세·지그 위치를 표시합니다. 고정 스텝은 지그 보정을 하지 않습니다. 계산은 백그라운드에서 처리하며, 계산 중이거나 도달 불가이면 이전 자세를 보정 결과처럼 표시하지 않고 사유를 보여줍니다. 이미 계산된 경로의 재생·일시정지는 해당 경로의 기준을 유지합니다. 3D 화면 아래에서 자세와 지그의 표시 출처를 구분합니다. 에피소드·편집 모터 틱·실물 명령은 변경하지 않으며 만료된 탐지값을 다시 유효하게 만들지 않습니다. 전체 맵 배경의 고정 완제품 팔레트는 티칭 화면에서 제외하여 등록 팔레트와 중복되지 않게 합니다.

저장된 로봇 설정은 목록 선택 즉시 불러옵니다. 연결·실행 중 허용되지 않는 설정 변경은 차단하고 선택 표시를 복원합니다. 리더 무게 보조는 화면·팔로워 최신값이 지연되면 기존 신선도 기준에서 토크 OFF와 설정 복원을 확인한 뒤 해제하되, 리더 읽기 연결은 유지합니다. 보조는 자동으로 다시 켜지지 않습니다. 실제 보정·장비 오류나 해제 실패는 기존 오류 정지를 유지하며 Pi의 리더 수신 2초 중단 정지도 유지합니다.

리더 따라가기의 최초 합류는 기존 스텝 빠르게와 같은 기본 400틱/초로 현재 자세에서 시작합니다. 설정·안내 → 로봇 → 최초 합류 속도에서 100/200/300/400틱/초를 선택하고 로봇 설정 저장·적용으로 저장합니다. 합류가 끝나면 평소 따라가기 속도는 750틱/초입니다. 다시 켤 때마다 현재 자세에서 합류하며, 통신 대기 후에도 초기 합류가 끝나지 않았으면 같은 최초 속도를 유지합니다.

실물 조정은 짧은 실물값 수신 지연에는 모드를 유지하고 새로운 조작 전송을 기다립니다. 최신값은 표시용 큐보다 장비 세션에서 직접 읽으며, 2초 이상 수신 중단·연결 오류·보정 불일치 때는 종료합니다. 실물 3D는 새 장면이 준비될 때까지 마지막 화면을 유지하고, 수신이 없으면 현재 위치가 아니라는 안내를 표시합니다.

실물 조정을 처음 켤 때 실행용 지그 측정이 필요하면 확정 전에는 검출을 동결하지 않습니다. 측정이 완료된 뒤 경로 계산·실물 이동 단계에서 기존처럼 지그 위치를 고정합니다.

통합 관제의 단순 ROS 명령 수신은 `./run_integration.sh`로 명시적으로 켭니다. `/arm2/episode_cmd`, `/arm3/episode_cmd`에 `std_msgs/msg/String`의 `A` 또는 `B`를 보내면 기존 에피소드 실행 경로를 사용하고, 마지막 요청의 실제 완료 후 해당 팔의 `episode_status`에 `A_DONE`/`B_DONE`을 발행합니다. 일반 실행은 명령을 받지 않습니다. 설정·명령·실패 메시지는 [INTEGRATION.md](INTEGRATION.md)를 참고하세요.

## Pi 에피소드 내보내기

티칭 화면에서 로봇팔과 에피소드를 선택한 뒤 **Pi 에피소드 내보내기**를 누릅니다. **설정·안내 → 에피소드 전송** 화면으로 이동하며, 저장된 SSH 연결 설정으로 현재 Pi의 A/B 실행 연결을 조회합니다.

1. 표시된 로봇팔·에피소드·스텝 수와 Pi 주소를 확인합니다.
2. 연결할 **A 또는 B**와 실행 제한시간을 선택합니다.
3. **Pi로 전송 · A/B 실행 연결**을 누릅니다.

전송 대상은 에피소드 목록의 저장된 스텝입니다. 입력칸에서 편집 중인 자세는 먼저 스텝 추가·수정으로 반영합니다. 전송은 선택한 팔의 A/B 항목 하나만 변경하고 로봇 실행을 시작하지 않습니다. PC와 Pi의 영점이 다르거나, 필요한 지그 모델이 없거나, Pi 작업이 실행 중이면 적용하지 않습니다. 조회 이후 Pi 설정·연결이 바뀌면 다시 조회해야 합니다.

Pi에는 별도 ID의 실행본을 생성하므로, 이후 PC의 원본을 수정·저장해도 A/B 실행본은 다시 내보내기 전까지 유지됩니다. Pi의 속도·지그 측정·보정 설정은 기존 `integration/execution-settings.json`과 팔별 설정을 사용합니다. 선택한 실행의 제한시간만 전송 화면 값으로 반영합니다. 통신이 끊겨 완료 응답을 받지 못하면 **Pi 실행 연결 조회**로 적용 여부를 확인합니다.

Pi의 `data/episode-transfer-backups/<전송 ID>/`에는 기존 `recipes.json`, 이전 실행 에피소드, 전송 기록과 완료 영수증을 보관합니다. 이전 에피소드 파일도 삭제하거나 덮어쓰지 않습니다. `recipes-before.json`은 당시 전체 연결의 백업이므로 수동 복원 시 이후 다른 팔·A/B 변경을 함께 되돌리지 않도록 선택 항목을 확인합니다.

### 앱 안전 종료

팔로워가 연결되지 않았거나, 연결된 모든 팔에서 최신 6개 모터의 토크 OFF가 확인되면 장치 연결만 정리하고 종료한다. Pi 통신 객체가 남아 있어도 두 팔 연결을 요구하지 않으며, 종료를 위해 토크를 새로 켜지 않는다.

안전 복귀가 필요한 팔이 있으면 **현재 연결된 팔만** Pi의 별도 종료 작업으로 인계한다. 한쪽만 연결되어 있으면 해당 팔의 저장된 안전자세만 검증·복귀하며, 미연결 팔은 연결하거나 명령하지 않는다. 두 팔이 연결되어 있으면 기존 순차 복귀를 유지한다. Pi의 인계 확인을 받으면 앱 창과 PC 연결을 닫고, Pi 작업이 자체 상태 감시를 유지하면서 안전자세 복귀·3초 정지·토크 OFF를 확인한 후 제어권과 공통 작업 잠금을 반환한다. 액션 서버는 계속 실행된다.

Pi 접수 전에 오류가 나면 앱을 유지하고 인계 실패를 표시한다. 접수 후 진행·완료·실패는 Pi의 작업 기록과 `work_watch`에 남긴다. 복귀에 실패하면 강제로 토크를 해제하지 않는다. 카메라 전용·미연결 화면은 장치 정리 후 종료한다. 일반 에피소드 실행의 두 팔 연결 조건은 유지하며, 한 팔 허용은 종료 복귀에만 적용한다.

2026-10-13 실물 연결 검증: 두 팔 읽기 연결, 팔3만 연결, Pi만 연결한 세 상태에서 종료를 확인했다. 12개 모터의 영점 일치·토크 OFF·통신 오류 없음과 상단 카메라 1280×720 영상을 확인했고, 모터 쓰기는 0건이었다. 한 팔 안전 복귀의 이동 순서·정지 확인·실패 시 해제 방지는 모의 장치로 검증했으며 이번에는 실물 복귀 이동을 수행하지 않았다. 자료는 `verification/real-connection-shutdown-20261013/`에 있다.

독립 실행과 `build_load_b` 같은 연속 실행 모두 이전 검사 이력을 다음 동작의 조건으로 읽지 않는다. 리니어 위 B는 현재 B 형상과 안착 위치로 판단한다. build 단계의 검사 실패는 기존대로 연속 실행을 중단하므로, load 단계에서 조립 이력을 다시 검사하지 않는다.


### 최신 데모와 화면 캡처

`bash SO101_teach/run.sh --demo`는 실사용과 같은 두 팔 작업창과 3D를 실행한다. 실행할 때 현재 설정·보정·지그·에피소드를 `SO101_teach/demo_sessions/<실행 시각>/`에 복사하며, 데모의 편집·저장·캡처는 이 복사본만 사용한다. 실제 모터·카메라·Pi 연결과 전송은 차단한다.

- 두 팔은 모의 모터값을 표시한다. 상단 카메라는 저장 영상으로 현재 검출·안착 검사·C안 이름표를 실행한다.
- `F6`: 정상 조립 / 오안착·미완성 영상 전환. 처음부터 오안착 영상을 보려면 `--demo --demo-scene faults`.
- `F7`: 영상 수신 중단 / 복구. 지연·만료 화면을 재현한다.
- `F8`: 현재 앱 화면을 데모 실행 폴더의 `captures/앱 화면/`에 저장한다. 검사 확인 중 또는 3D 초기화 중이면 최대 10초 기다리고, 준비되지 않으면 저장하지 않는다.
- 카메라 자동 재생을 끄려면 `--demo --no-camera`. 카메라 연결 버튼으로 저장 영상 재생을 시작할 수 있다.
- 저장 영상은 `tests/fixtures/inspection-all`의 기록이다. 실제 조립 동작에 따라 물체가 움직이는 물리 시뮬레이션은 아니다. 영상/판정 기록에는 데모 재생 여부와 장면을 남긴다.

전체 앱 캡처는 단일 `App` 테스트에 설정을 뒤늦게 덮어쓰지 말고, `prepare_data` → `ArmWorkspaces(mode_override='demo')` → `activate`의 정식 데모 경로를 사용한다. `tests/test_demo_capture.py`가 숨긴 1920×1080 디스플레이에서 이 경로를 검증한다.


2026-10-13 오류 이미지 기록은 원본과 표시본을 쌍으로 저장한다. `inspection.jpg` / `inspection-annotated.jpg`는 검사에 사용한 동일 프레임의 원본·판정 표시, `jig-confirmed.jpg` / `jig-confirmed-annotated.jpg`는 실행에 사용한 지그 확정 프레임의 원본·확정 위치 표시다. 확정 프레임은 일반 수신 캐시에서 제거되어도 한 장을 따로 보존한다. 지그 검출·마지막 수신 프레임도 각각 원본·표시본으로 저장하며, 판정과 시각이 다른 마지막 수신 프레임에는 과거 판정 결과를 겹치지 않는다. 원본은 수신 JPEG 바이트를 그대로 보존하고, 표시본만 새 JPEG로 인코딩한다. 오류 기록 화면에서 ‘검사 원본 / 검사 판정 표시 / 지그 확정 원본 / 지그 확정 표시’를 선택할 수 있다. 수신한 프레임이 없거나 표시본 생성이 실패하면 이유를 로그에 남기고 원래 오류와 원본을 보존한다. 오류 저장을 위해 카메라를 새로 열거나 검출·판정을 다시 실행하지 않는다.

목표 분리와 이미지 기록 변경의 검증·배포 자료는 `verification/tcp_goal_anchor_20261013/`에 있다. Pi의 표시본 생성에는 `requirements-pi.txt`의 Pillow와 함께 배포되는 `assets/fonts/NanumGothic.ttf`를 사용한다. 원래 오류 기록은 변경하지 않는다.
