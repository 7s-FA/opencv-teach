# Raspberry Pi 5에서 OpenCV 티칭 사용

## 2026-10-02: 8GB Pi로 이전

현재 연결 대상은 `ubuntu@192.0.2.10`(arm3, Ubuntu 24.04, aarch64, Python 3.12.3)입니다. 프로그램과 Python 경로는 아래 표와 동일합니다. PC의 `data/pi-connection.json`도 113으로 변경했습니다. 기존 112의 프로그램과 데이터는 유지했습니다.

PC 최신 코드와 112의 보정·지그·에피소드를 복사했습니다. OS·CPU 구조·Python 버전·설치 경로가 같음을 확인하고 112의 가상환경을 복제했으며, `pip check`, 모터 라이브러리 로드, 보정·역기구학 초기화, 카메라 1280×720 프레임 15장, 지그 영상 처리, PC→113 SSH 통신과 코드 버전 일치를 확인했습니다. 이번 이전에서 모터 연결·토크 켜기·이동은 실행하지 않았습니다.

113의 기본 게이트웨이를 `192.0.2.10`에서 실제 응답하는 `192.0.2.10`로 수정하여 외부 통신을 복구했습니다. `systemd-timesyncd`를 부팅 시 활성화하고 `ntp.ubuntu.com`을 통한 실제 동기화(`System clock synchronized: yes`)를 확인했습니다. 시간대는 `Asia/Seoul`입니다.

113에서 USB 시리얼 `5B91027630`, `5B91028218` 두 장치와 Innomaker 카메라가 보입니다. 이전 당시 기존 팔로워 포트 `5B91027630` 설정을 유지했습니다. 현재는 해당 포트를 팔2, `5B91028218`을 팔3으로 구분합니다. 팔3은 초기 연결용 보정 상태이며 실측 보정을 완료해야 합니다. 이전 당시 앱은 PC 리더 + Pi 팔로워 1대 구조였습니다. 이후 아래의 팔 선택 기능을 추가했으며, 두 팔의 동시 제어는 포함하지 않습니다. 이번 작업은 기존 OpenCV 실행 환경의 이전입니다.

이전 검증 자료: PC의 `verification/pi113-migration-20261002`, Pi의 `verification/pi113`. 실행 중이던 PC 앱은 다시 열어 변경된 연결 대상을 적용합니다.

PC에서 현재 SO-101 티칭 앱을 열고 **설정·안내 → 라즈베리파이 연결 → Pi 연결·사용**을 누릅니다. 연결 정보는 입력해 두었습니다. 이후에는 왼쪽 아래에 `장치: Pi`가 표시됩니다. 모터 토크는 자동으로 켜지지 않습니다.

팔로워와 상단 카메라의 Pi 연결을 확인했습니다. 리더암은 PC에 연결해 사용합니다.

1. PC 앱의 로봇 연결을 종료한 뒤 팔로워 USB와 상단 카메라를 Pi에 연결합니다. 리더암 USB는 PC에 유지합니다.
2. **Pi 연결·사용**을 누릅니다. 같은 화면에서 Pi가 확인한 USB 포트와 카메라 경로를 확인합니다.
3. 기존 USB 장치를 그대로 옮기면 `/dev/serial/by-id`, `/dev/v4l/by-id` 경로를 그대로 사용할 수 있습니다. 다른 장치는 **설정·안내 → 로봇 / 카메라 보정**에서 경로를 변경합니다. 리더를 사용할 때는 PC 리더 포트와 리더 보정 JSON을 등록하고 **리더 + 팔로워**를 선택합니다. 리더를 연결하지 않을 때는 **팔로워 단독**을 선택합니다.
4. 앱 시작 시 Pi 연결 후 팔로워를 자동 연결해 현재 모터 틱을 읽습니다. 리더+팔로워 모드에서는 PC의 리더도 자동 연결합니다. 토크 켜기와 리더 따라가기는 버튼을 눌러 시작합니다. 상단 카메라에서 영상·지그 위치를 확인합니다. 자동 연결이 실패하면 **팔로워 연결**로 다시 시도합니다.
5. 현재 자세 유지, 리더 따라가기, 스텝 저장, 경로 미리보기, 에피소드 실행은 기존 버튼을 그대로 사용합니다.

**이 PC 사용**을 누르면 장치 연결 대상이 PC로 돌아옵니다. 로봇 연결을 종료한 상태에서 전환합니다. 선택한 연결 대상은 다음 실행에도 유지되며, Pi 연결 실패 시 PC USB로 자동 전환하지 않습니다.

## 설치된 구성

| 항목 | 위치/역할 |
|---|---|
| Pi 프로그램 | `/home/ubuntu/OpenCV_teach` |
| Pi Python | `/home/ubuntu/so101-player/.venv/bin/python` — 기존 가상환경 재사용 |
| PC 프로그램 | `/path/to/Final_Arm/SO101_teach` |
| PC 연결 설정 | `data/pi-connection.json` |
| Pi 설정·영점·지그·에피소드 | `/home/ubuntu/OpenCV_teach/data` |
| Pi 모터 진단 기록 | `/home/ubuntu/OpenCV_teach/data/diagnostics` |
| PC에서 영상 저장 | PC 앱의 `data/captures` — 표시된 감지 정보 포함 |

PC는 화면, 3D, 저장 편집과 오프라인 카메라 보정 사진 계산을 담당합니다. PC는 리더암의 USB 읽기와 리더 3점 보정도 담당합니다. Pi는 팔로워 모터 읽기·구동, 리더→팔로워 변환, 카메라 촬영·지그 검출, 실행용 역기구학 계산을 담당합니다. 촬영·검출·영상 전송은 최대 10 FPS, 3D는 최대 30 FPS입니다. PC에서 리더의 최신 틱을 최대 초당 50회 Pi로 전송합니다. Pi는 리더의 ±90°·0° 각도 기준을 팔로워의 보정 기준으로 변환하고 팔로워 범위 안으로 제한합니다. 집게는 닫힘·열림 범위를 따로 변환합니다. 오래되거나 순서가 뒤바뀐 리더 표본은 사용하지 않습니다. 팔로워 제어 루프는 Pi 안에서 실행됩니다.

PC의 현재 영점 JSON·3점 각도 파일·TCP·카메라 보정·지그 STL·감지 범위를 Pi에 전송합니다. 현재 영점과 호환되는 에피소드를 복사하고 이후 저장·삭제도 반영합니다. 다른 영점으로 저장된 옛 에피소드는 자동 변환하지 않습니다. 리더 보정은 PC에서 수행합니다. Pi에서 팔로워 새 보정을 완료하면 결과 JSON과 `.angles.json`을 PC로 가져와 적용합니다. 보정 도중 통신이 끊기면 작업을 취소하고 기존 보정을 복원합니다. 최종 저장 직후 연결이 끊겨 PC에 결과가 도착하지 않았다면 Pi의 `data/calibration`에 저장한 파일을 확인해야 합니다.

## 실행 방식

**Pi 연결·사용**이 SSH 키 인증으로 Pi 실행부를 시작하고 전용 통신 통로를 엽니다. 비밀번호는 저장하지 않습니다. Pi 실행부는 `127.0.0.1:8765`에서만 대기하며 외부 네트워크에 직접 공개되지 않습니다. 부팅 자동 실행 서비스는 설치하지 않았습니다.

Pi에서 직접 실행부를 확인할 때:

```bash
cd /home/ubuntu/OpenCV_teach
./run_pi.sh
```

이미 PC에서 실행부를 시작한 경우에는 중복 실행하지 않습니다. PC와 Pi의 코드 버전이 다르면 원칙적으로 연결을 중단하므로 양쪽 프로그램을 함께 갱신합니다. 이번 PC 통신 수정처럼 모터 제어·계산 코드가 그대로임을 대조한 경우에는 확인된 정확한 버전 조합만 허용하여 Pi의 자세 유지 상태를 보존할 수 있습니다.

리더 값 전송이 일시적으로 지연되면 최신 표본으로 다시 전송하고 팔로워 연결은 유지합니다. 에피소드가 Pi에서 실행되는 동안에는 리더 표본 전송을 쉬고, 끝난 뒤 다시 최신 표본을 보냅니다. Pi 상태 조회도 짧은 지연은 재시도합니다. 이동·토크 명령은 처리 여부를 모르는 상태에서 자동 재전송하지 않습니다.

PC 응답이 2초 이상 끊기면 Pi가 이동을 멈추고 자세를 유지합니다. 재연결만으로 이동을 다시 시작하지 않습니다. 통신 실패 명령을 자동 재전송하지 않아 토크 켜기나 이동이 중복 실행되지 않습니다. 다시 연결하면 Pi가 유지 중인 로봇 상태를 화면에 복원합니다.

현재 `/home/ubuntu/so101-player`는 활성 가상환경을 보관하는 경로입니다. 실행 소스는 `/home/ubuntu/OpenCV_teach`이며 별도의 `/home/ubuntu/SO101_teach` 경로를 전제로 실행하지 않습니다. 기존 가상환경에 추가한 계산·영상 패키지는 `requirements-pi.txt`에 기록했으며, 설치 전·후 목록은 Pi 폴더의 `environment-before.txt`, `environment-after.txt`에 있습니다.

## 초기 Pi 적용 때의 검증 기록

실제 SSH 연결, 설정·에피소드 전송, Pi의 모터 통신 라이브러리 구성, 기록 영상의 지그 검출, PC/Pi의 같은 경로 계산, 장치 미연결 오류, 연결 소유권·중복 명령·통신 지연·취소 처리를 확인했습니다. 실제 10개 스텝 계산에서 PC와 Pi의 목표 모터 틱이 모두 같았습니다.

팔로워 6개 서보를 Pi USB로 읽어 저장된 영점과 일치하는 것을 확인했습니다. 점검 시 토크는 모두 OFF, 전압은 12.1~12.3V, 온도는 34~38°C였고 쓰기 패킷은 0개였습니다. Pi 카메라의 1280×720 실시간 영상과 팔레트 검출도 확인했습니다. PC→Pi 모의 리더 전송은 약 초당 47회였고 변환값이 일치했습니다. **실제 리더를 움직이는 동기화와 팔로워의 물리적 이동·집기 실행은 아직 검증하지 않았습니다.** 검증 기록은 `verification/pi-runtime`에 있습니다.

전송 지연·복구·실제 연결 오류는 PC의 `data/diagnostics/pi-link-*.json`에도 기록됩니다. 리더 전송 지연과 팔로워 제어 연결 오류를 구분해서 표시합니다.


## 2026-10-02: 선택한 팔 하나의 티칭·실행

PC와 Pi 실행부에 같은 버전의 팔 구분 기능을 적용합니다. 상단 선택기로 팔2(`…27630`) 또는 팔3(`…28218`)을 선택합니다. Pi 실행 세션은 선택한 팔 하나를 담당하며, 팔을 바꾸기 전에 기존 읽기 연결을 정리합니다. 활성 동작·토크 유지·보정 중에는 전환하지 않습니다.

기존 에피소드는 팔2 전용이고, 팔3은 새 3점 보정을 완료해야 연결·실행할 수 있습니다. 팔3 보정 진행 파일은 Pi의 `data/calibration_progress/follower-arm3.json`입니다. 초기 연결용 JSON은 모터 적용용 보정이 아니며 양쪽 프로그램에서 적용을 거부합니다. 카메라와 리니어 상태 조회는 공유하고, 팔3 감지 좌표는 해당 팔의 베이스 기준으로 변환합니다. 팔별 물리적 보정은 각 팔의 보정 화면에서 사용자가 직접 진행합니다.

## 최신 모델과 점검 기준

운반용 지그는 새 B 상단이 포함된 `06a99f0b…` 조립본을 사용합니다. 설정 묶음은 등록 STL을 전송하며, 작업대·버거·체결부·리니어와 같은 표시 자산은 코드 배포 때 함께 맞춥니다. 코드 버전은 모든 Python 소스와 지정된 모델 파일을 반영하지만, 모든 표시 자산의 동일성을 대신하지는 않습니다. 따라서 최신 정합성 점검에서는 전체 실행 자산의 해시도 따로 대조합니다.

팔별 프로필 목록은 PC에 있고 Pi는 마지막으로 구성한 팔의 활성 프로필을 가집니다. 두 호스트의 `profile.json` 경로 문자열과 선택 상태가 다르다는 사실만으로 오류로 판정하지 않습니다. 보정 원본 해시·모델 기준·팔 ID와 등록 STL의 내용을 대조합니다.

실물 읽기 검사는 `ReadOnlySession`의 전송 게이트로 PING·READ·SYNC_READ만 허용하고 종료 시 포트만 닫습니다. 토크 OFF·이동·EEPROM 명령을 보내는 보정/구동 세션과 구분합니다. 사용자 운영 중인 포트를 빼앗거나 기존 세션을 종료하지 않습니다. 최신 점검 자료는 `verification/latest-consistency-audit`에 있습니다.

## 팔별 연결 유지

팔2는 기본 실행부(루프백 8765), 팔3은 별도 실행부(루프백 8766)를 사용한다. 팔3의 실행 상태·설정·인증 정보는 `data/arm3-runtime`에 저장한다. 두 연결은 각각 상태 확인과 heartbeat를 유지하며 팔 선택으로 종료하거나 명령을 재전송하지 않는다. `python -m so101_teach.remote_server --ensure --arm arm2` 또는 `--arm arm3`으로 해당 실행부만 준비한다. 프로그램 갱신은 두 실행부 모두 장치 연결과 실행을 종료한 상태에서 진행한다.


## 리니어·관제 서비스

2026-10-07부터 리니어는 전진 100mm / 후진 1.5mm 두 목표와 전진·후진·중간(INTERMEDIATE) 상태를 구분합니다. 비상정지 시 남은 시간을 보관하고 재시작하면 남은 시간+1초를 재구동합니다. 실제 위치 센서값이 아닌 시간 기준 완료이며 중간 위치를 끝점으로 표시하지 않습니다.

리니어 실행부는 `arm3-linear-controller.service`, 관제 Action은 `workcell-actions.service`입니다. 명령·알림·서비스 설치·로그 경로는 [INTEGRATION.md](INTEGRATION.md)를 따릅니다. 기존 최종 명령 파일은 호환 기록으로 유지하며, 현재 진행 상태는 앱과 독립적인 `motion.json`에 저장합니다. 재시작 시 자동으로 PWM을 출력하거나 이전 작업을 재개하지 않습니다.
