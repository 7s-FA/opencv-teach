PC에서 현재 SO-101 티칭 앱을 열고 **설정·안내 → 라즈베리파이 연결 → Pi 대상으로 선택**을 누릅니다. 연결 정보는 입력해 두었습니다. 이후에는 왼쪽 아래에 `장치: Pi`가 표시됩니다. 모터 토크는 자동으로 켜지지 않습니다.

팔로워와 상단 카메라의 Pi 연결을 확인했습니다. 리더암은 PC에 연결해 사용합니다.

1. PC 앱의 로봇 연결을 종료한 뒤 팔로워 USB와 상단 카메라를 Pi에 연결합니다. 리더암 USB는 PC에 유지합니다.
2. **Pi 대상으로 선택**을 누릅니다. 이 버튼은 대상 설정만 저장합니다. 실제 제어 연결은 상단 **전체 연결**을 눌러 요청하며, 연결 후 설정 화면에서 Pi USB 포트와 카메라 경로를 확인합니다.
3. 기존 USB 장치를 그대로 옮기면 `/dev/serial/by-id`, `/dev/v4l/by-id` 경로를 그대로 사용할 수 있습니다. 다른 장치는 **설정·안내 → 로봇 / 카메라 보정**에서 경로를 변경합니다. 리더를 사용할 때는 PC 리더 포트와 리더 보정 JSON을 등록하고 **리더 + 팔로워**를 선택합니다. 리더를 연결하지 않을 때는 **팔로워 단독**을 선택합니다.
4. 앱은 조회 전용으로 시작합니다. **전체 연결**을 누르면 팔로워의 제어권을 요청하고 현재 모터 틱을 읽습니다. 리더+팔로워 모드에서는 PC 리더도 연결합니다. 토크 켜기와 리더 따라가기는 별도 조작입니다. Pi 공정이 사용 중이면 한 번 거절되고 자동 재시도하지 않습니다. 연결이 끊긴 경우도 **전체 연결**을 다시 눌러야 합니다.
5. 현재 자세 유지, 리더 따라가기, 스텝 저장, 경로 미리보기, 에피소드 실행은 기존 버튼을 그대로 사용합니다.

**이 PC 사용**을 누르면 장치 연결 대상이 PC로 돌아옵니다. 로봇 연결을 종료한 상태에서 전환합니다. 선택한 연결 대상은 다음 실행에도 유지되며, Pi 연결 실패 시 PC USB로 자동 전환하지 않습니다.

## 실행 방식

**전체 연결**이 SSH 키 인증으로 Pi 실행부를 시작하고 전용 통신 통로를 엽니다. 비밀번호는 저장하지 않습니다. Pi 실행부는 팔2 `127.0.0.1:8765`, 팔3 `127.0.0.1:8766`에서 대기하며 외부 네트워크에 직접 공개되지 않습니다. 부팅 자동 실행 서비스는 설치하지 않았습니다.

Pi에서 직접 실행부를 확인할 때:

```bash
cd /home/ubuntu/OpenCV_teach
./run_pi.sh
```

이미 PC에서 실행부를 시작한 경우에는 중복 실행하지 않습니다. 현재 PC–Pi 연결은 아래의 공통 실행 코드 버전을 기준으로 판단합니다. 화면 코드 변경만으로 Pi 갱신이나 버전 허용 목록 편집이 필요하지 않습니다.

리더 값 전송이 일시적으로 지연되면 최신 표본으로 다시 전송하고 팔로워 연결은 유지합니다. 에피소드가 Pi에서 실행되는 동안에는 리더 표본 전송을 쉬고, 끝난 뒤 다시 최신 표본을 보냅니다. Pi 상태 조회도 짧은 지연은 재시도합니다. 이동·토크 명령은 처리 여부를 모르는 상태에서 자동 재전송하지 않습니다.

PC 응답이 2초 이상 끊기면 Pi가 이동을 멈추고 자세를 유지합니다. 자동 재연결하지 않으며, **전체 연결**을 다시 눌러야 합니다. 재연결만으로 이동을 다시 시작하지 않습니다. 통신 실패 명령을 자동 재전송하지 않아 토크 켜기나 이동이 중복 실행되지 않습니다. 다시 연결하면 Pi가 유지 중인 로봇 상태를 화면에 복원합니다.

현재 `/home/ubuntu/so101-player`는 활성 가상환경을 보관하는 경로입니다. 실행 소스는 `/home/ubuntu/OpenCV_teach`이며 별도의 `/home/ubuntu/SO101_teach` 경로를 전제로 실행하지 않습니다. 기존 가상환경에 추가한 계산·영상 패키지는 `requirements-pi.txt`에 기록했으며, 설치 전·후 목록은 Pi 폴더의 `environment-before.txt`, `environment-after.txt`에 있습니다.

## 초기 Pi 적용 때의 검증 기록

실제 SSH 연결, 설정·에피소드 전송, Pi의 모터 통신 라이브러리 구성, 기록 영상의 지그 검출, PC/Pi의 같은 경로 계산, 장치 미연결 오류, 연결 소유권·중복 명령·통신 지연·취소 처리를 확인했습니다. 실제 10개 스텝 계산에서 PC와 Pi의 목표 모터 틱이 모두 같았습니다.

팔로워 6개 서보를 Pi USB로 읽어 저장된 영점과 일치하는 것을 확인했습니다. 점검 시 토크는 모두 OFF, 전압은 12.1~12.3V, 온도는 34~38°C였고 쓰기 패킷은 0개였습니다. Pi 카메라의 1280×720 실시간 영상과 팔레트 검출도 확인했습니다. PC→Pi 모의 리더 전송은 약 초당 47회였고 변환값이 일치했습니다. **실제 리더를 움직이는 동기화와 팔로워의 물리적 이동·집기 실행은 아직 검증하지 않았습니다.** 검증 기록은 `verification/pi-runtime`에 있습니다.

전송 지연·복구·실제 연결 오류는 PC의 `data/diagnostics/pi-link-*.json`에도 기록됩니다. 리더 전송 지연과 팔로워 제어 연결 오류를 구분해서 표시합니다.


## 2026-10-02: 선택한 팔 하나의 티칭·실행

PC와 Pi 실행부에 같은 버전의 팔 구분 기능을 적용합니다. 상단 선택기로 팔2(`…27630`) 또는 팔3(`…28218`)을 선택합니다. Pi 실행 세션은 선택한 팔 하나를 담당하며, 팔을 바꾸기 전에 기존 읽기 연결을 정리합니다. 활성 동작·토크 유지·보정 중에는 전환하지 않습니다.

기존 에피소드는 팔2 전용이고, 팔3은 새 3점 보정을 완료해야 연결·실행할 수 있습니다. 팔3 보정 진행 파일은 Pi의 `data/calibration_progress/follower-arm3.json`입니다. 초기 연결용 JSON은 모터 적용용 보정이 아니며 양쪽 프로그램에서 적용을 거부합니다. 카메라와 리니어 상태 조회는 공유하고, 팔3 감지 좌표는 해당 팔의 베이스 기준으로 변환합니다. 팔별 물리적 보정은 각 팔의 보정 화면에서 사용자가 직접 진행합니다.

## 최신 모델과 점검 기준

운반용 지그는 새 B 상단이 포함된 `06a99f0b…` 조립본을 사용합니다. 설정 묶음은 등록 STL을 전송하며, 작업대·버거·체결부·리니어와 같은 표시 자산은 코드 배포 때 함께 맞춥니다. 코드 버전은 모든 Python 소스와 지정된 모델 파일을 반영하지만, 모든 표시 자산의 동일성을 대신하지는 않습니다. 따라서 최신 정합성 점검에서는 전체 실행 자산의 해시도 따로 대조합니다.

팔별 프로필 목록은 PC에 있고 Pi는 마지막으로 구성한 팔의 활성 프로필을 가집니다. 두 호스트의 `profile.json` 경로 문자열과 선택 상태가 다르다는 사실만으로 오류로 판정하지 않습니다. 보정 원본 해시·모델 기준·팔 ID와 등록 STL의 내용을 대조합니다.

## 현재 버전 연동과 갱신 · 2026-10-13

전체 앱의 `version`은 진단용으로 유지합니다. 실제 연결은 `PROTOCOL`과 `runtime` 파일 해시를 비교합니다. 실행부 시작 시 읽은 해시를 `/health`에 고정해 반환하므로 디스크만 바뀌고 프로세스가 오래된 상태도 구분합니다. 통신 터널을 연 뒤에도 인스턴스와 실행 버전을 다시 확인한 후 제어권을 얻습니다.

- `runtime_version.py`에 명시한 화면·3D 모듈은 공통 실행 버전에서 제외합니다. `ui.py`, 미리보기, 재질, 화면 위젯 변경은 Pi 연결과 실행부 재시작을 요구하지 않습니다.
- 모터·통신·검사·안전 종료·공통 계산 코드와 실제 검사에 쓰이는 모델·검사 기준 자산은 일치해야 합니다. 리니어 계산은 `linear_geometry.py`, 작업대 좌표 읽기·변환은 `workcell_placement.py`로 분리했습니다. 기존 화면 모듈은 같은 함수를 다시 내보내므로 계산은 중복하지 않습니다.
- 새로운 Python 모듈은 기본적으로 공통 실행 버전에 포함합니다. 실행 코드가 제외된 화면 모듈을 가져오면 검사에서 실패합니다. 새로운 화면 전용 분류는 `runtime_version.py`의 검토·동기화가 필요합니다. `integration/*.before_*.py`처럼 Python 모듈 이름이 아닌 과거 사본은 제외합니다.
- 프로필·보정·지그·에피소드는 기존 설정 동기화와 해시 검증을 유지합니다. 소스 동기화 도구가 `data/`의 사용자 기록을 덮어쓰지 않습니다.
